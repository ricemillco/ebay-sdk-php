Base: `v18.0.8`, commit `0aec735e22fd0e65f4c38d4ee24a3cc0b07e37eb`,
the fork's default `master` branch at preparation time.

Prepared on the existing `fix/php-8.4-compatibility` branch at `a1b7598b`.
That branch already contains the constructor corrections and other PHP 8.4
compatibility fixes. Its existing work is preserved; the additional changes
provide focused constructor regression coverage, JSON response parsing
fixes, and release notes.

## Changes

PHP 8.3 deprecated calls to `get_parent_class()` without an argument. Replace
all 2,746 such calls: 2,735 SDK source files and 11 test fixtures. For this
constructor correction, each affected PHP file changes only `get_parent_class()`
to `get_parent_class(__CLASS__)`.
This includes the Taxonomy request, response, aspect metadata, aspect, constraint,
and value constructors used by Atlantis.

`__CLASS__` identifies the class containing each constructor. When a response's
constructor calls its parent's constructor, that parent must look up its own
parent's metadata. Passing `$this` or `static::class` instead would identify the
most derived object's parent, changing the lookup and potentially reading an
uninitialized metadata cache. The regression runner constructs the child first
with an empty cache and checks both parent and child metadata independently.

The constructor correction changes no public signatures, dependency constraints,
or error-reporting settings in production code. Deprecations are fixed at their
source. The branch's other existing PHP 8.4 fixes are outside this description.

JSON response parsing also handles empty, whitespace-only, PHP null and JSON
`null` bodies without changing the response's properties, status or headers.
Malformed JSON (including HTML error bodies) raises an `UnexpectedValueException`
with the JSON decoder's error message and code. Non-null scalar JSON raises an
`UnexpectedValueException` explaining that an object or array was expected.
This avoids passing null or another scalar to the array-only property parser
while keeping invalid response payloads visible to callers. Valid nested object
parsing, unknown-field handling, and null-field filtering are preserved.

## Validation

Run from this SDK repository, without installing any dependencies:

```sh
make test-compatibility
# Or run each suite separately:
php test/compatibility/get-parent-class.php
php test/compatibility/json-parser.php
```

The runner enables `E_ALL` and converts all reported warnings and deprecations
to exceptions. It checks cold and warm metadata caches, inherited constructor
values, Trading request metadata, nested Taxonomy JSON parsing, and constructs
all 2,735 affected SDK types with a fresh metadata cache for each type. The
standard `make test` target also runs these checks before the PHPUnit suite.

The JSON parser runner reproduces the reported null-array argument error before
the fix and passes on PHP 8.3.36 and 8.4.27 afterward. It checks empty/null bodies,
malformed JSON, HTML, invalid UTF-8, excessive nesting, scalar JSON, and valid
nested responses. Warnings and deprecations fail the suite.

The runner passes on PHP 8.2.35, 8.3.36 and 8.4.27. The unpatched constructors
fail on PHP 8.3 with the targeted deprecation. The same tests also pass against
the unpatched source on PHP 8.2, confirming the original metadata behavior.
Temporary mutations using `$this`, `static::class`, or no argument in the
`AspectMetadata` constructor all fail the regression on PHP 8.3.
Syntax checks pass on PHP 7.4, 8.3 and 8.4 for every modified PHP file and the
new runner. Composer validation
passes. The full legacy PHPUnit suite was not run: this checkout has no
`vendor/bin/phpunit`, and its declared PHPUnit `~4.0` predates PHP 8.3.

The argument form and all newly added PHP syntax are available on PHP 5.5.
The manifest continues to declare PHP `>=5.5`. However, the existing default
branch already contains scalar return types and `mixed` return types in
`src/Types/RepeatableType.php`. On PHP 7.4 the runtime regression stops at its
existing `mixed` return type, which PHP 7.4 interprets as a class name. This patch
does not introduce that limitation or repair it, and is not a certification
that the whole package runs on PHP 5.5–7.4. No PHP 5.5 runtime was available.

PHP reference: [deprecation and lexical context](https://wiki.php.net/rfc/deprecate_functions_with_overloaded_signatures).
