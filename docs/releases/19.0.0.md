# Proposed v19.0.0 release (unreleased)

Base: `v18.0.8`, commit `0aec735e22fd0e65f4c38d4ee24a3cc0b07e37eb`,
the fork's default `master` branch at preparation time.

Prepared on the existing `fix/php-8.4-compatibility` branch at `a1b7598b`.
That branch already contains the constructor corrections and other PHP 8.4
compatibility fixes. Its existing work is preserved; the additional changes
provide focused constructor regression coverage, JSON response parsing
fixes, and release notes.

## Breaking changes

This is a major release because existing code can behave differently:

- PHP `>=8.0` is required, replacing `>=5.5`.
- REST and OAuth responses with a whitespace-only or JSON `null` body now return an
  empty response instead of raising a `TypeError`, even with an error status. Check
  `getStatusCode()` rather than relying on an exception.
- REST and OAuth responses with malformed JSON or a scalar body now raise
  `UnexpectedValueException` instead of `TypeError`. Code catching `\TypeError` must
  catch the new exception. `catch (\Exception)` now catches these failures.

## Changes

PHP 8.3 deprecated calls to `get_parent_class()` without an argument. Replace
all 2,746 such calls: 2,735 SDK source files and 11 test fixtures. For this
constructor correction, each affected PHP file changes only `get_parent_class()`
to `get_parent_class(__CLASS__)`.
This includes the Taxonomy request, response, aspect metadata, aspect, constraint,
and value constructors used by Atlantis.

`__CLASS__` identifies the class containing each constructor. When a response's
constructor calls its parent's constructor, that parent must look up its own
parent's metadata. Passing `$this` or `static::class` instead would identify the
most derived object's parent, changing the lookup and potentially reading an
uninitialized metadata cache. The regression runner constructs the child first
with an empty cache and checks both parent and child metadata independently.

The constructor correction changes no public signatures, dependency constraints,
or error-reporting settings in production code. Deprecations are fixed at their
source. The branch's other existing PHP 8.4 fixes are outside this description.

JSON response parsing also handles empty, whitespace-only, PHP null and JSON
`null` bodies without changing the response's properties, status or headers.
Malformed JSON (including HTML error bodies) raises an `UnexpectedValueException`
with the JSON decoder's error message and code. Non-null scalar JSON raises an
`UnexpectedValueException` explaining that an object or array was expected.
This avoids passing null or another scalar to the array-only property parser
while keeping invalid response payloads visible to callers. Valid nested object
parsing, unknown-field handling, and null-field filtering are preserved.

OAuth responses are built through their constructors rather than the property
parser, so `OAuthService` shares this decoding through the new
`JsonParser::decode()` method. Valid OAuth responses are built as before, including
the `UnknownPropertyException` for an unknown field.

These are behaviour changes for REST and OAuth callers. Malformed and scalar bodies
previously raised a `TypeError`, which `catch (\Exception)` does not catch.
Whitespace-only and JSON `null` bodies previously raised the same error and now
return an empty response, even with an error status, so callers must check
`getStatusCode()`.

## Validation

Run from this SDK repository, without installing any dependencies:

```sh
make test-compatibility
# Or run each suite separately:
php test/compatibility/get-parent-class.php
php test/compatibility/json-parser.php
php test/compatibility/runtime.php
```

`runtime.php` compiles the SDK's non-type source files and covers XML parsing,
JMESPath and the OAuth redirect URL. Its OAuth and REST HTTP checks need Guzzle and
are reported as skipped unless `vendor/autoload.php` exists. To install it:

```sh
composer remove --dev --no-update phpunit/phpunit squizlabs/php_codesniffer
composer update --no-dev
```

Do not commit the resulting `composer.json` change. GitHub Actions runs these steps
and the runners on PHP 8.0, 8.3 and 8.4.

The runner enables `E_ALL` and converts all reported warnings and deprecations
to exceptions. It checks cold and warm metadata caches, inherited constructor
values, Trading request metadata, nested Taxonomy JSON parsing, and constructs
all 2,735 affected SDK types with a fresh metadata cache for each type. The
standard `make test` target also runs these checks before the PHPUnit suite.

The JSON parser runner reproduces the reported null-array argument error before
the fix and passes on PHP 8.3.36 and 8.4.27 afterward. It checks empty/null bodies,
malformed JSON, HTML, invalid UTF-8, excessive nesting, scalar JSON, and valid
nested responses. Warnings and deprecations fail the suite.

The runner passes on PHP 8.2.35, 8.3.36 and 8.4.27. The unpatched constructors
fail on PHP 8.3 with the targeted deprecation. The same tests also pass against
the unpatched source on PHP 8.2, confirming the original metadata behavior.
Temporary mutations using `$this`, `static::class`, or no argument in the
`AspectMetadata` constructor all fail the regression on PHP 8.3.
Syntax checks pass on PHP 7.4, 8.3 and 8.4 for every modified PHP file and the
new runner. Composer validation
passes.

The declared development tools (PHPUnit `~4.0` and PHP_CodeSniffer `2.*`) can no
longer be installed because Composer blocks them over security advisories, and
PHPUnit 4 predates PHP 8.3. The legacy suite was run once using PHPUnit 9.6 and a
temporary, uncommitted shim for its old class names and `setUp()` signatures. With
deprecations as errors on PHP 8.3.36 and 8.4.27, 6,552 of 6,554 tests pass:
`ServiceTest::testOptionalEbayHeaders` also fails without this release, and
`UriResolverTest::testAllowsValid` reports `urlencode(null)` when a query parameter
callable returns null. Typed request properties reject null, so requests built from
them do not reach that call.

The manifest now requires PHP `>=8.0` instead of `>=5.5`. The existing default
branch already contains `mixed` return types in `src/Types/RepeatableType.php`.
On PHP 7.4 the runtime regression stops at that return type, which PHP 7.4 interprets
as a class name, so this only blocks versions that were already broken. This
branch's explicit nullable parameters also need PHP 7.1.

No PHP 8.0 runtime was available when preparing this release. The compatibility
runners pass on PHP 8.1, 8.3 and 8.4. GitHub Actions adds PHP 8.0, so check that job's
first run before tagging the release.

PHP reference: [deprecation and lexical context](https://wiki.php.net/rfc/deprecate_functions_with_overloaded_signatures).

## Atlantis update after release

Do this in Atlantis's source checkout only after the fork's `v19.0.0` tag is
available. No Atlantis files have been changed here.

1. Keep the package name `dts/ebay-sdk-php`. Ensure Atlantis's root
   `composer.json` resolves it from the Ricemill fork. Merge this repository
   entry with any existing entries, retaining the intended repository priority:

   ```json
   {
     "repositories": [
       {
         "type": "vcs",
         "url": "https://github.com/ricemillco/ebay-sdk-php"
       }
     ],
     "require": {
       "dts/ebay-sdk-php": "^19.0"
     }
   }
   ```

   This is a fragment to merge into the existing manifest. If Atlantis pins
   exact versions, use `19.0.0` instead. Remove any old explicit commit pin for
   this package. A `^18` constraint does not permit this release, so it must be
   changed. Atlantis must run on PHP 8.0 or later.

2. Update the lock through Composer, rather than editing it manually:

   ```sh
   composer update dts/ebay-sdk-php --with-dependencies
   composer validate --strict
   composer show --locked dts/ebay-sdk-php
   git diff -- composer.json composer.lock
   ```

   With Composer versions that support it, add `--minimal-changes` to the update
   command to reduce transitive dependency changes. Review the lock diff: the
   SDK should resolve to `v19.0.0` (or a later approved release), from the Ricemill
   fork, with `source.reference` and any `dist.reference` pointing to that release's
   commit rather than `0aec735e22fd0e65f4c38d4ee24a3cc0b07e37eb`.

3. Review Atlantis's handling of the breaking changes above, especially any code
   that catches `\TypeError` or relies on an exception for an empty or error response.
   Run Atlantis's relevant tests and Taxonomy item-aspects flow on PHP 8.3 or
   later with deprecations enabled. Review and commit both `composer.json` and
   `composer.lock` together under Atlantis's normal workflow. Deploy from the
   reviewed lock file with `composer install`; do not edit `vendor/`.
